# WIUT Hackathon 2026 - Computer Vision

Система компьютерного зрения для анализа дорожного движения по видео с фиксированной камеры
Проект разработан для трека *Computer Vision* хакатона WIUT 2026.
Система анализирует дорожное видео, обнаруживает транспортные средства и пешеходов, отслеживает их движение, определяет дорожные события и рассчитывает текущий потенциальный риск столкновения.
Также в проекте есть локальный веб-интерфейс на Flask для визуализации работы алгоритма в реальном времени.

# Возможности

Система выполняет:

- обнаружение объектов с помощью YOLO11n;
- обнаружение автомобилей, автобусов, грузовиков, мотоциклов и пешеходов;
- отслеживание объектов между запусками YOLO;
- определение дорожных событий;
- формирование временных сегментов событий;
- расчёт потенциального риска столкновения;
- оценку TTC (Time To Collision);
- расчёт относительной скорости объектов;
- расчёт расстояния между объектами;
- поиск наиболее опасной пары транспортных средств;
- выделение потенциально опасных автомобилей красной рамкой;
- генерацию `predictions.json`;
- проверку результата через `evaluate.py`;
- локальную визуализацию через Flask.


# Поддерживаемые события
Алгоритм работает со следующими классами:

1. `accident` — авария
2. `near_miss` — потенциально опасное сближение
3. `red_light` — проезд на красный свет
4. `wrong_way` — движение в неправильном направлении
5. `illegal_u_turn` — незаконный разворот
6. `stopped_vehicle` — остановившийся автомобиль
7. `jaywalking` — переход дороги в неположенном месте
8. `failure_to_yield` — непредоставление преимущества
9. `illegal_turn` — незаконный поворот
10. `solid_line_crossing` — пересечение сплошной линии
11. `stop_line` — пересечение стоп-линии
12. `congestion` — дорожный затор
13. `road_obstacle` — препятствие на дороге
14. `fire_smoke` — огонь или дым

Визуализация потенциального столкновения

Система дополнительно ищет пару транспортных средств с максимальным текущим парным риском.

Если риск пары достигает установленного порога, соответствующие автомобили выделяются красным.

Например:

RISK      0.603
TTC       0.58s

CONFLICT #4 <-> #7

На видео:

        ┌──────────────────┐
        │ #4 car           │
        │ POTENTIAL        │
        │ COLLISION        │
        └──────────────────┘
                🔴


                    ┌──────────────────┐
                    │ #7 car           │
                    │ POTENTIAL        │
                    │ COLLISION        │
                    └──────────────────┘
                            🔴

Остальные автомобили продолжают отображаться обычной рамкой.

Что означает Risk

Значение:

Risk = 0.603

не означает:

Вероятность аварии = 60.3%

Risk — это текущий эвристический показатель потенциальной опасности.

Он рассчитывается на основе нескольких характеристик движения:

TTC;
относительной скорости;
расстояния между объектами;
пересечения bounding box;
динамики движения объектов.

Например:

Risk       0.603
TTC        0.58 s
Rel Speed  0.0929
Distance   0.0301

Такая комбинация означает, что алгоритм видит сильный сигнал потенциального столкновения при текущем движении объектов.

Однако автомобиль может:

затормозить;
изменить направление;
перестроиться;
остановиться;
продолжить движение по другой траектории.

Поэтому Risk не является гарантией того, что авария произойдёт.

Почему YOLO запускается не на каждом кадре

Для снижения нагрузки на CPU YOLO запускается с определённой периодичностью.

Между запусками детектора используется tracker.

Схема:

Кадр 1       YOLO
              │
              ▼
           Tracker
              │
Кадры 2-15 ──┤
              │
              ▼
Кадр 16      YOLO
              │
              ▼
           Tracker

Это позволяет уменьшить вычислительную нагрузку и одновременно сохранять траектории объектов.

Processing FPS

Показатель:

Processing FPS

характеризует скорость обработки/цикла визуализации Flask.

Он не является фактическим FPS инференса YOLO.

YOLO запускается только на определённых кадрах, а между ними работает tracker.
